# 电脑与无线链路

## 身份和使用权

设备最多记住八台电脑。每台电脑使用持久的随机 32 字符客户端 ID、独立的
64 字符凭据和显示名称。名称、IP 和蓝牙地址不作为身份依据。Wi-Fi 和 BLE
共用该 ID 和凭据，客户端将其保存在当前账户的私有配置文件中，不调用钥匙串。

旧版单一配对凭据会成为一个待迁移记录。原客户端证明持有旧凭据后，设备先保存
其持久 ID 和名称，再接受连接。原 Wi-Fi、设备设置和电台列表的存储格式及键名保留。

同一时刻只有一台电脑拥有语音、回车、设置修改和 Agent 提醒的使用权。
其他已配对电脑可以验证身份、查看占用状态，并点击“切换到本机”主动接管。
发现广播不会抢占正常连接。设备显示当前电脑名称，重名电脑仍使用独立身份。

## 配对

设备进入“设备设置 → 配对电脑”显示六位配对码。桌面端通过局域网或 BLE
发现设备后输入此码。尚未配对时首页也显示配对码。通过任一链路配对后，同一
客户端的另一链路自动获得应用层授权，无需重复输入配对码。系统蓝牙权限和
操作系统管理的蓝牙绑定与应用配对分开。

仅使用蓝牙时不需要先配网。Wi-Fi 仍通过原有手机配网页面添加。
同时关闭两个无线开关后，需要在设备本机重新开启。“解除所有配对”只清除
电脑凭据，不清除已保存 Wi-Fi 或电台列表。

电脑丢失本地凭据但仍保留客户端 ID 时，输入设备当前配对码可只替换该电脑的
凭据，不影响其他电脑，也不额外占用配对名额；保存失败则不改变原记录。
已配对的非当前电脑即使 BLE 已待机断开，也可以点击“切换到本机”，重新连接后接管。

## 选路和重连

设备保留 UDP 发现端口 33333，电脑由系统分配可用端口，并向各个有效 IPv4
局域网发送发现广播。设备向实际来源地址和端口回复。客户端每 10 秒通过可用
链路发送一次经过身份验证的 `pc.status`，合并语音就绪状态和设备校时信息。
设备在连续三个周期未收到状态时判定链路失效。

首次选择可用链路，两条都已知时优先 Wi-Fi；正常连接后保持原链路。
故障时先尝试同一台电脑的另一条已验证链路，再考虑其他已配对电脑。
Wi-Fi 恢复不会抢走正常的 BLE 链路。使用权改变或当前端点替换会更新本次
开机范围内的租约编号。控制请求必须同时带上当前开机标识和租约编号；旧使用者
延迟到达的接管请求会被拒绝，当前使用者重试已成功的接管不会重复切换。旧使用者的延迟请求、已排队
的回车事件和剩余语音不会发给新电脑。客户端拒绝旧租约和已经退出的开机标识，
在使用权、链路或设备开机标识改变时释放快捷键。录音中断链可能结束本次输入，
不承诺无损、无缝切换。

协议 3 的 HELLO 和事件计数必须是完整的无符号 32 位整数，错误消息不能清除
客户端的版本检查；已建立的协议 3 会话不能降级为协议 2。设备先广播使用权变化、
后回复请求时，第一条有效的当前使用权消息即可确认接管，避免误报失败。
协议 3 控制格式要求开机标识，固件与客户端需要配套更新；客户端首次连接
仍兼容已发布的协议 2 固件。

## BLE

设备作为 NimBLE 外围设备，不主动扫描。最多同时连接两台电脑：当前使用者，
以及一条临时查询或接管连接。仍有空位时继续广播。临时连接 30 秒内没有成为
当前使用者便断开；非当前客户端主动释放该连接，用户点击接管时重新连接。
记住八台电脑不代表长期保持八条蓝牙连接。
打开客户端窗口只刷新就绪状态，不会重新占用已释放的 BLE 连接；手动刷新和
主动接管才可重新启用发现。

客户端收到设备蓝牙已关闭的新状态后，停止 BLE 扫描和重连。通过 Wi-Fi 重新
开启蓝牙后恢复发现；没有 Wi-Fi 时，在设备本机重新开启后可手动刷新发现。
开启无线连接不会取消另一台电脑的使用权，也不会让待机客户端自行接管。
BLE 调度独立于局域网套接字创建，后者失败不会停止蓝牙心跳和请求超时处理。

首次生成并在 NVS 保存一份静态随机 BLE 地址，重启和切换电脑都不改变，
与原固件公开蓝牙地址及其系统配对缓存分开。跨链路仍以 GATT 中的出厂设备 ID
识别同一设备；不能每次开机换地址来掩盖配对保存问题。
Mac 仅在核验 GATT 出厂设备 ID 后缓存系统的外围设备 UUID，重连时先尝试找回该
外围设备，再扫描；缓存 UUID 不能替代设备身份核验或授权。

服务 UUID 为 `6F6C6F56-6962-436F-8D11-0B4DE2C07400`：

| 末尾 | 用途 |
| --- | --- |
| `01` | 读取稳定的设备 ID，再选择对应凭据 |
| `02` | 加密、带响应的 GATT 写入，接收控制消息 |
| `03` | 通过通知发送回复、事件和 ADPCM 音频 |

两端将原有带类型字节的数据包分片，增加六字节小端头：消息编号、偏移和完整包长。
按协商后的 MTU 分片，应用单次特征值最多 244 字节。重组上限 1,537 字节，
拒绝不连续分片，超过 2 秒清理。设备仅在接收命令时分配重组缓冲。
语音沿用每包独立的 100 毫秒 IMA ADPCM 和常驻 3,200 字节 PCM 缓冲。

## 内存和省电约定

电脑记录和路由状态使用固定、有限的结构，不为每台电脑增加任务。
JSON 队列只增加来源元数据，不内嵌整包缓冲。BLE 内存池在协议栈启动时按设定
上限分配，关闭时释放，不挪用收音机保留的 16 KiB 网络与控制余量。
网络任务启动前只准备 BLE 适配器的锁；界面及 Wi-Fi 常驻分配完成后，再由网络
任务启动蓝牙主机和控制器。不要把长期存活的 Wi-Fi 分配穿插在 BLE 内存池中，
否则关闭蓝牙也不能合并被 Wi-Fi 活跃块隔开的空洞。
关闭蓝牙时先停止并等待主机任务
退出，再反初始化协议栈；不调用会导致本次开机无法重新启用 BLE 的不可逆内存
释放接口。关闭 Wi-Fi 会停止其无线收发与连接尝试。
ESP-IDF 5.5.3 的按块动态内存池与动态上下文释放组合存在 ATT／GATT 释放顺序
和池清理问题。因此显式关闭 `BT_NIMBLE_MEMPOOL_RUNTIME_ALLOC`，保留
`BT_NIMBLE_STATIC_TO_DYNAMIC`。不修改 SDK，不通过关闭断言掩盖泄漏，也不
永久保留蓝牙池绕过退出问题。升级 SDK 后必须重新验证启停与内存回收。
启停期间短暂持有 `vibe_ble_switch` 浅睡眠锁，正常返回后释放；待机不持有。

复用网络任务，通过 UDP 和一个内部 eventfd 一起等待。即使所有 IP 网卡关闭，
BLE 命令也能唤醒任务；不新增任务或定时轮询，也不用为本机唤醒分配 UDP 包。
BLE 状态锁不跨越 NimBLE 调用；单独的发送锁串行化分片与协议栈退出，
主机回调不获取发送锁，避免同步回调与底层锁造成相互等待。
恢复 TX 订阅的事件可能先于 SDK 的连接完成回调，后者不能清空前者；其他特征值
的订阅事件不能改变本服务 TX 状态。HCI 队列短暂拥堵时，在有界期限内重试同一
分片，不另加常驻发送缓存。

控制器与低速主机代码放入 Flash，回收可选 IRAM，保留连续堆空间，不压缩语音
保留区和收音机安全余量。擦写 Flash 可能延迟 BLE 处理，因此必须实测 NVS 保存、
配对保存、语音吞吐和重连。未确认 Flash 芯片兼容前，不启用专用自动挂起选项。
HCI 队列按两条连接设上限，不保留通用扫描器默认的大队列。

闲置 BLE 请求外围设备延迟，仅在语音实际使用 BLE 时请求低延迟连接参数，实际参数可由电脑协商
调整。广播间隔 0.8～1 秒，设备不扫描，不随每个 BLE 连接事件发送应用心跳。
BLE 控制请求重试间隔为 3 秒，避免在闲置连接延迟下过早重复发送。无线开关改变
后，即使旧链路的确认包丢失，也可由新链路中通过身份、使用权和租约检查且开关
值一致的 HELLO 确认结果；不能用旧状态或其他使用者的 HELLO 判为成功。
旧链路先断开时，只保留无线开关操作等待确认，恢复使用权前不重发；12 秒内
没有新状态确认则超时。其他旧链路操作立即丢弃，不在新链路重放。
保留调制解调器睡眠和自动浅睡眠。本板使用主晶振维持 BLE 睡眠时钟，不能通过
软件设置补出外部 32 kHz 晶振。睡眠比例和堆统计不能代替电流测量。

## 电脑转发收音机

收音机由当前电脑通过已选 Wi-Fi 或 BLE 链路转发。电脑拉取并解码 MP3／AAC／HLS，
转换为 24 kHz 单声道，再发送独立的 50 ms IMA ADPCM 块。设备不保留收音机 HTTP／HLS／TLS、
AAC／MP3 解码器、读取任务或独立 PCM 工作区；非录音时复用常驻的 3,200 字节语音 PCM。
电脑必须保持唤醒、联网并运行客户端；通过 BLE 收听时可以关闭设备 Wi-Fi。

设备按会话申请两或三块 7,852 字节缓冲，共 26 或 39 帧，即 15,704 或 23,556 字节，
约 1.3 或 1.95 秒。先初始化音频格式再做准入，保留 16 KiB 控制／网络堆；
两块都无法满足时拒绝启动。不为每个电台新增常驻队列或任务。
累计额度限制电脑只发送接收端可容纳的帧；重复、缺口、错误链路和旧会话均不能扩张 FIFO。
每次会话生成随机编号，绑定当前使用者链路和租约。收听时每 200 ms 重复报告额度，
电脑从缺失帧开始有限重发，不扩张窗口。闲置时没有音频轮询或转码进程。

电脑最多缓存 200 个编码块，约 118 KiB／10 秒，满后阻塞生产者。
客户端内置固定源码校验值的精简 LGPL FFmpeg 子进程，同时携带对应源码压缩包、许可证及完整构建脚本；
不依赖 Homebrew 或运行时下载。电台只接受 HTTP／HTTPS 输入。
语音、退出、换台、电脑／链路切换或失败时停止进程、待发音频和接收会话；
松开语音后以新会话恢复直播。连接／读取和进程退出均有限时，不能为了快一点恢复就保留大块内存。

保留必须驻留的中断代码、栈保护、显示／音频 DMA 与调制解调器睡眠。
天气仍使用证书验证的 HTTPS 和动态 TLS 缓冲。镜像变小、设备申请减少不能证明实际电流降低，
两种链路、语音抢占和长时间收听仍需真机验证。

## 验证边界

主机测试覆盖旧配对迁移及保存失败、电脑重名、链路保持、两电脑接管、同电脑
故障转移、HCI 连接句柄复用、旧请求、有限分片、错误输入和租约编号回绕。
还包含 100,000 次确定性的使用权操作，以及通过真实本机套接字验证桌面消息
处理流程，覆盖旧设置、旧开机事件、先广播后回复的接管确认和降级拒绝。
它们不能证明天线性能、实际 BLE 吞吐、两台真实电脑的系统行为、播放音质或电流。
这些结果应关联具体固件，记录在实现记录中。
