# 设备连接

电脑通过局域网广播或附近的 BLE 广播发现设备，同一台设备合并成一行。
BLE 支持语音、按键、设置、收音机播放、电台列表、待机诊断和 Agent 提醒。
收音机由电脑联网取流和解码，再通过任一链路发送音频；需要电脑 App 运行并联网，
设备可以只连接蓝牙。电脑也通过任一链路发送精简天气／空气质量缓存。
设备直连天气下载保留为有 Wi-Fi 且内存足够时的回退方式。

## 首次连接

首屏介绍蓝牙和 Wi-Fi，右侧三颗实体键分别对应蓝牙、Wi-Fi、稍后。
BLE 广播从开机开始，不需要先选择蓝牙或配置 Wi-Fi。
蓝牙入口显示电脑端操作和设备尾号；Wi-Fi 入口才开启手机配网热点。
Wi-Fi 联网成功后继续等待电脑确认，不将联网当作配对完成。
选择稍后会持久保存，已配对设备升级也不会重复新手引导。
设备设置中保留连接电脑和 Wi-Fi 两个独立入口。
取消或超时不清除 Wi-Fi、原电脑授权或引导进度；黑屏唤醒的整次手势不能误触确认。

## 连接与换电脑

1. 安装配套固件和桌面端，允许蓝牙／局域网访问。
2. 在“连接与语音”中点击设备的“连接”。编号末四位用于区分设备。
3. 设备亮屏显示申请连接的电脑名称。按上键确认，按下键或设置键取消。
4. 首次授权后自动重连。同一电脑的 Wi-Fi 和 BLE 可同时连接，健康的主链路保持不变，
   Wi-Fi 恢复也不抢占正常的蓝牙。持续故障时使用另一条已认证链路，无需重新确认。

另一台电脑也可直接申请连接；设备提示切换电脑，确认后才撤销原电脑的授权。
拒绝、取消或超时不会解除原绑定。旧电脑发现授权失效后暂停重连，不争抢设备。
“断开连接”保留授权并暂停重连；“解除配对”撤销电脑的应用授权，保留 Wi-Fi 记录及系统级
BLE 加密绑定。保留蓝牙绑定不能执行未授权命令，也不能绕过新的设备按键确认。
只清理单侧蓝牙密钥会造成 macOS 的旧配对失效，因此不属于解除电脑配对操作。
切换到另一台设备前，App 会询问是否丢弃未保存的设置。

## 确认协议与边界

桌面端区分“正在发出申请”和“设备已回复待确认”，只有匹配申请的待确认回执才提示
在设备上确认；重复回执不延长等待时间。BLE 链路失败后按 3、6、12、24、48、最多
60 秒退避，新的广播不能绕过间隔；用户主动选择设备或收到有效业务数据后清除退避。
此策略减少连续失败的重试风暴，不绕过 macOS 的连接限制。
自动连接由新收到的可连接 BLE 广播触发，不因缓存中仍有设备身份就反复连接已停止广播
的蓝牙；用户主动重试仍可明确发起。
如果 macOS 明确报告对端配对信息已删除，停止自动 BLE 重试，并显示系统蓝牙设置入口；
忽略旧系统记录后由用户主动重试，不中断仍正常工作的 Wi-Fi 会话。

局域网控制、发现和收音音频使用 UDP 33333。音频携带随机会话号和有界序号窗口，
通过接收位图补发缺包，重复包不重复播放。BLE 支持相同的音频和控制能力。发现回复只含设备身份、占用和能力信息，不改变控制目标；
凭据不放入发现广播。新连接使用 `connection.request`，携带客户端 UUID、申请 UUID、
电脑的 ASCII 名称别名及候选凭据的 SHA-256 摘要。同一申请可经两条链路重复发送，
不会延长确认时间，也不会覆盖另一台电脑正在等待的申请。

设备有四十五秒等待按键确认；同意后有二十秒完成凭据提交。提交必须匹配已确认的
客户端、申请和摘要，且成功保存后才替换原授权。旧版配对码不能绕过设备确认。
录音时返回忙；电脑可取消申请。电脑名称是显示信息，并不是可信身份认证。

BLE 服务 UUID 为 `71DF1000-7B51-4A1D-A9B3-5A7669626532`；只读元数据特征为
`1001`，加密写入特征为 `1002`，通知特征为 `1003`，后缀相同。
广播名 `Vibe-<12位十六进制编号>` 与 Wi-Fi 的设备 ID 一致。
BLE 使用 LE Secure Connections 的 Just Works 加密绑定，不再要求输入数字码；
它不提供经过认证的 MITM 防护，应用控制权由设备按键确认及保存的凭据决定。
局域网 UDP 不提供链路加密，适用于可信局域网。

设备保留两个 BLE 连接名额，便于另一台电脑申请换机；它们不代表允许两台电脑同时控制。
每条 BLE 连接独立组包，七字节头为 `0x56`、消息编号、开始／结束位、小端总长度和偏移。
组装上限 1537 字节，超时两秒。Wi-Fi 和 BLE 共用一套应用协议与授权，
两条链路的加入不改变会话代次；换电脑后旧代次的排队命令失效。
旧协议音频只走主链路；协商后的 V2 语音沿双链路发送并在电脑合并。
开始、结束录音及按键等关键事件沿两条已授权链路发送同一事件 ID，
桌面端去重后才执行。音频序号用于丢包／重复检查。

认证后的 `pc.status` 心跳携带 `primaryTransport`（`wifi` 或 `bluetooth`）。
桌面端在接收链路选择变化时立即报告，避免 Wi-Fi 单向故障时设备继续向失效方向发送。
设备仅在 BLE 链路新鲜时采用该偏好，否则仍使用可用的 Wi-Fi；旧版客户端未携带字段时
保留原自动选择逻辑。


## 链路稳定与拥塞

下文按音频情况切换路由的规则用于旧协议录音。V2 已经双发，仅保留控制链路持续无响应或明确断开时的切换。

一包恢复的心跳不会抢占正常链路。备用链路在三秒内收到过已认证数据时，当前链路
连续六秒无响应、明确断开，或录音连续三秒没有音频，才可切换。完整五秒窗口内有至少二十个音频序号位置且缺失达到 70%，也视为严重故障。音频断流或严重丢包触发的
切换有十五秒保持期；明确断开或持续无响应可越过保持期。新录音与刚切换的链路
都有音频启动宽限。原有四点五秒无音频释放按键保护不变，双链路失效不会卡住快捷键。
轻微抖动或信号弱本身不触发切换。两端统一使用六秒链路窗口，健康蓝牙不会自动切回 Wi-Fi。

设备发送通知前，按完整 mbuf 链预估分配成本，同时检查总空闲块和实际使用的缓冲池。
语音分配后保留四个池内块、六个总空闲块；拥塞时，工作任务在三十毫秒语音预算或
五十毫秒控制预算内等待，回调不等待。不增加音频积压队列，也不扩大缓冲池。
桌面端对 ATT 拥塞保留同一分片，按一百、二百五十、五百和一千毫秒退避重试，
新写入不能插队。成功后重置退避，断连或服务更换后旧重试失效。
资源或队列不足不再显示为配对失败。日志保留错误域与错误码、分链路语音包数、
停止原因、缓冲池余量、空闲堆和最大空闲块。

## 电脑休眠

系统休眠时，桌面端立即拦截新的设备任务，并释放按住的快捷键。
随后在所属队列停止 BLE 扫描、蓝牙连接、局域网套接字、语音、电台音频及定时活动。
休眠通知不等待网络队列、音频驱动或子进程启动；先关闭通信，再释放音频。
排队的定时回调和旧权限检测结果不能重新启动任务。

桌面端依据 `NSWorkspace.didWakeNotification` 恢复，不依赖显示器状态。
仅屏幕息屏、亮屏不改变连接，后台维护唤醒不会恢复通信。
主动打开 App 或点击连接，可以恢复遗漏唤醒通知时的通信。
重复唤醒不会创建额外的蓝牙管理器。配对授权、设置草稿和主动断开状态在休眠及
自动权限重载后保持。语音不会自行重新录制；设备仍请求播放时，收音机重新连接。

额度查询取消自己创建的子进程，取消操作不等待持锁的进程启动。
因休眠中断的查询，在唤醒且来源最近活跃时可再次执行；成功查询仍保持五分钟间隔，
真正失败的查询仍保留退避，缓存数据不延长原有效期。

## 验收

主机测试覆盖身份合并、双链路保留、切换、拒绝、超时、忙、错误摘要、旧授权失效、
分包边界和连接代次。实机仍需检查双电脑／多设备、确认页面及按键、两条链路的重连、
语音／回车、Agent 提醒、设置同步、切换延迟、共存内存及休眠行为。

设备已授权后，关闭桌面端，运行
`<installed-app>/Contents/MacOS/VibeCompanion --ble-device-test`。
该检查使用九十秒验收窗口与真实连接引擎但不开局域网套接字，读取设置和电台列表、
提交原亮度值、发送一次 Agent 测试提醒，并检查一分钟 BLE 可用性。
它不进行配对，也不绕过设备确认；检查后重新打开桌面端。
